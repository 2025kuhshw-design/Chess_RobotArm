# 문제 해결 기록

이 프로젝트에서 실제로 막혔던 지점과 해결 방법. 보고서·재현·인수인계용.
설계안에는 없었고 **실물을 만든 뒤에야 드러난 문제**가 대부분이다.

---

## 1. 기구학 / 좌표계 — 가장 치명적이었던 부류

| 문제 | 증상 | 원인 | 해결 |
|---|---|---|---|
| **어깨 높이 누락** | 모든 칸이 서보 범위 밖, 체스판에 닿지도 못함 | IK가 어깨 관절을 체스판과 **같은 높이**로 가정. 실제로는 8.9cm 위 | `SHOULDER_HEIGHT` 파라미터 신설 (`ik_solver.py`) |
| **팔꿈치 방향 반대** | 위와 동일 | 2링크 IK는 해가 둘(elbow-up/down)인데 한쪽만 사용. 실제 팔은 반대 | `ELBOW_SIGN` 스위치 추가, `-1`(down)로 설정 |
| **좌표계 거울상** | 방향을 맞춰도 좌우가 뒤집힘 | 카메라 격자→로봇 좌표 변환이 왼손 좌표계 | 4방향 매핑을 오른손계로 재도출, 외적 부호로 검증 |
| **랭크·파일 축 반전** | 사람이 둔 수를 엔진이 **전부 불법으로 판정** | 랭크가 좌우 방향에 배정돼, 사람 앞 두 줄이 랭크1·2가 아니라 g·h 파일이 됨 | `chess_square_to_xyz`에서 랭크를 로봇↔사람 방향(x)으로 수정 |
| **도달 범위 부족** | 중앙 4×4 중 9칸만 도달 | 보드 배치가 팔 가동범위와 안 맞음 | 배치 탐색 → 근단 x=11cm, 우단 y=−6cm. 중앙·흑진영 전부 도달(46/64) |
| **리프트 높이 고정** | `ValueError: 도달 불가능한 좌표` 로 게임 중단 | 먼 칸에서 고정 8cm 리프트가 팔 길이 초과 | 칸별 적응형 `_safe_lift()` |
| **캡처 위치 초과** | 기물 잡기 시 크래시 | 잡은 칸에서 x+5cm 지점이 반경 초과(0.301>0.295m) | 보드 밖 고정 캡처 구역(4×2 슬롯) 신설 |
| **범위 초과 무시** | 못 가는 칸인데 경고 없이 엉뚱한 위치로 | `_rad_to_servo`가 조용히 클램프 | 범위 밖이면 `ValueError` 발생시키도록 변경 |

> **교훈**: 시뮬레이터에서 완벽했던 정책도, 물리 파라미터 2개가 빠지면 시작조차 못 한다.

## 2. 하드웨어 손상 — 실제로 부품이 망가진 사고

| 문제 | 원인 | 해결 |
|---|---|---|
| **서보 기어 파손** (칠판 긁는 소리) | 큰 각도를 한 번에 명령 → 최고속 이동 중 스톨/충격 | 목표까지 2°씩 나눠 보내는 **램프 제어** 도입. `--step`/`--step-delay`로 속도 조절 |
| **모터 드라이버 소손** | 펌프 인러시(순간 수 A)가 PCA9685의 얇은 전원 트레이스를 통과 | 펌프/밸브 **V+를 외부전원에 직결**. PCA는 신호만 담당 |
| **부팅 시 팔이 튐** | `.ino`의 `setup()`이 무조건 90,90,90으로 이동 | 부팅 시 서보 출력을 끈 채 대기하도록 변경 |
| **첫 명령에서 팔이 튐** | 서보에 위치 센서가 없어 출발점을 모름 → 램프 불가 | **기동 절차**(`engage`→`park`→`start`) 도입. 현재 각도를 사람이 알려줌 |

> **교훈**: 서보는 명령받은 위치로 자기 최대 속도로 간다. 속도를 늦추는 유일한 방법은
> 중간 위치를 잘게 나눠 보내는 것이고, 그러려면 **출발 위치를 알아야** 한다.

## 3. 흡착 시스템

| 문제 | 원인 | 해결 |
|---|---|---|
| 흡착기 무반응 | 모듈이 상시 HIGH가 아니라 **서보 펄스**로 켜지는 방식(FZ006류) | `.ino`에서 ON=2.4ms / OFF=0.5ms 펄스로 변경 |
| 채널 불일치 | 실제 배선이 ch4/ch5인데 코드는 ch3/ch4 | `CH_PUMP=4`, `CH_VALVE=5` |
| **집자마자 기물을 놓음** | `_move_to`가 `suction` 인자를 안 받아 매 호출마다 OFF로 덮어씀 | 이동 전 구간에 `suction=True` 명시 전달. 놓는 지점을 한 곳으로 정리 |
| `suction` 명령이 팔을 움직임 | 흡착만 토글하지 않고 리프트 좌표로 이동 | 현재 서보각을 그대로 재전송하도록 수정 |
| 흡착이 안 걸림 | 하강 목표가 기물 윗면 정확히 → 고무컵이 안 눌림 | `TOUCH_PRESS`(기본 4mm) 추가. `zoff <mm>`로 실시간 조정 |

## 4. 카메라 / 비전

| 문제 | 원인 | 해결 |
|---|---|---|
| **탑뷰 격자가 어긋남** | 캘리브레이션에서 **칸 중앙**을 클릭. 중앙끼리는 7칸인데 8칸으로 분할 | 8×8 바깥 모서리를 클릭하도록 안내. `--click centers` 모드 추가(중앙 클릭 시 자동 환산) |
| 보드 가장자리 왜곡 | 광각 렌즈 배럴 디스토션 — 퍼스펙티브 변환은 변이 직선이라고 가정 | 보드가 화면의 70~80%만 차지하도록 여유 확보 |
| 마커 미검출 | 두 프로그램이 카메라를 동시에 사용 / 자동노출 안정화 전 프레임 | 워밍업 8프레임, 재시도 5회, 실패 원인 안내 |
| 마커에 보드가 잡힘 | 노랑이 나무색과 색상(H)이 겹침 | 채도(S) 최소값을 높게(130). `MARKER_MAX_AREA`로 큰 덩어리 배제 |
| 라이브 뷰 멈춤 | `input()`이 블로킹이라 GUI 이벤트 루프가 안 돎 | 백그라운드 스레드가 read→그리기→waitKey 반복. 뷰 스레드가 카메라 읽기 독점 |
| 팔이 보드를 가림 | 로봇 차례에 팔이 카메라 시야를 막음 | 보드 읽기 직전 `arm.home()`. 연속 2회 동일할 때만 채택(`get_stable_board_state`) |
| 이동 감지 실패 | 글자를 타이핑함 (실제로 말을 안 옮김) | `--mode real`은 물리적으로 옮긴 뒤 Enter |

## 5. 정확도 보정 — 접근 방식 자체를 바꾼 부분

| 단계 | 방법 | 결과 |
|---|---|---|
| ① 시뮬 RL | PyBullet에서 학습한 보정 정책 | ❌ **실제 오차를 못 줄임.** 실물을 본 적이 없으므로 원리상 불가 |
| ② 실측 보정 | 격자를 눈금 삼아 오차를 재고 어파인 피팅 (`calibrate_board.py`) | ⭕ 계통 오차 제거. 단 **유격이 있으면 매번 달라져 한계** |
| ③ **카메라 폐루프** | 흡착컵 마커를 보고 오차만큼 재이동 (`visual_align.py`) | ✅ 유격이 있어도 대응. 시뮬 검증 17mm→3mm |

> **교훈**: 정확도를 실제로 올린 것은 강화학습이 아니라 **실제로 재고 되먹이는 것**이었다.
> 시뮬 RL은 "해석적 IK ↔ 시뮬 동역학"의 차이를 학습할 뿐, 실물 오차와 무관하다.

**기존 RL 모델을 못 쓰게 된 경위**: 기구학을 수정하자 관절각 범위가 학습 당시와
**0°도 겹치지 않게** 됨(q3는 부호까지 반대). 모델이 본 적 없는 입력이라 출력이 무의미.

## 6. 개발 환경

| 문제 | 원인·해결 |
|---|---|
| `No module named 'serial'` | 패키지명은 `pyserial`, 임포트명은 `serial` |
| `PermissionError` (COM 포트) | Arduino IDE **시리얼 모니터가 포트 점유** → 닫기 |
| 응답이 `'READY'` | 부팅 메시지가 버퍼에 남음 → `reset_input_buffer()` |
| numpy·pybullet 빌드 실패 | **Python 3.14 사용** — 사전빌드 wheel 없음 → 3.11/3.12로 |
| venv가 base Python을 못 찾음 | 3.14를 삭제해 venv가 깨짐 → `py -3.12 -m venv venv`로 재생성 |
| pip `cp949` 디코딩 오류 | `requirements.txt`의 한글 주석 → 영문으로 |
| pybullet 설치 불가 (Windows) | **Windows용 wheel이 아예 없음**(Linux만) → MSVC 빌드도구 or Colab |
| pybullet DLL 차단 | **Smart App Control / Device Guard**가 서명 없는 DLL 차단 |
| RL 모델 로드 크래시 | 학습·실행 환경 버전 불일치 → `PPO.load(custom_objects={"learning_rate":0.0, ...})` |
| Colab clone 실패 | 저장소가 **비공개** + 이름 대소문자(`Chess_RobotArm`) → zip 업로드 방식 |
| Colab 드라이브 마운트 실패 | `!python`은 별도 프로세스라 커널 접근 불가 → 노트북 셀에서 먼저 마운트 |

## 7. 재발 방지 장치

문제를 겪은 뒤 코드에 넣은 것들.

- **펌웨어 버전 확인** — `.ino` 재업로드를 빠뜨리면 연결 시 경고 (`fw=3 ✓`)
- **소프트 각도 제한** (`SERVO_SAFE_MIN/MAX`) — 구조물에 처박히는 각도 차단
- **범위 초과 시 명시적 실패** — 조용한 클램프 금지
- **정착 대기** (`SETTLE_WAIT`) — 팔 진동(3~4Hz)이 잦아든 뒤 하강
- **하강 전 사람 확인** (`--confirm`) — 첫 실전 안전장치
- **도달 지도** (`check` 명령) — 어느 칸이 닿는지 즉시 확인
- **기동 절차** — 전원 인가 직후 슬램 방지
